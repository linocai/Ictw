## [LRN-20260728-001] correction

**Logged**: 2026-07-28T15:30:00+08:00
**Priority**: high
**Status**: pending
**Area**: infra

### Summary

中国大陆服务器使用非标准 HTTPS 端口不能作为规避 ICP 备案的合规迁移路线。

### Details

工信部规则按“在境内通过域名或 IP 提供互联网信息服务”判断，并不以 80/443 端口为边界。非标准端口不免除备案义务，已备案域名迁入新的境内接入商时也应核对接入备案。

### Suggested Action

境内服务使用合规的 ICP／接入备案路线；不得把非标准 HTTPS 端口描述为备案替代方案。

### Summary

灵感创造师只需要“有有效历史的承接模式”和“历史不足的自由发想模式”；空白章节属于自由发想，不应再拆成第三种模式或成为失败条件。

生产中三次灵感请求均完成两轮模型输出且 `finish_reason=stop`，六次都被确定性校验拒绝。历史材料不足只应改变上下文与可选来源字段，不应让整批灵感失败。前期章节、零有效归档、空 Bible、无人选择都必须进入同一个自由发想降级路径。

### Suggested Action

由程序根据有效历史决定承接或自由发想；自由发想固定清空历史引用。校验按卡片保留有效结果，安全丢弃无效可选元数据，只有最终不足三张有效卡片时才进行一次定向修复并报错。

## [LRN-20260811-003] correction

**Logged**: 2026-08-11T00:00:00+08:00
**Priority**: high
**Status**: promoted
**Area**: backend
**Promoted**: `AGENTS.md`

### Summary

灵感创造师的“场景化”是弹性构思方法，不是要暴露给用户的固定场景模板；已定章节标题是锚点，Agent 不得另拟标题。

### Details

把灵感硬拆为起因／行动／冲突／转折或“场景一、二、三”会压扁文学性章节。正确做法是让 Agent 在构思时可用若干自然衔接的场景呈现章节进程，同时允许单一持续场景、内心思考、人物互动、个人动作、回忆、意象或环境流动。对外仍是一段自然连贯的剧情可能性，介于一句话梗概与正式正文之间。

### Suggested Action

模型输入协议不再要求创意 `title`，由服务器为旧客户端映射固定“方向一”等标签；已有章节标题明确标为不可改拟的锚点。Prompt 要求使用可感知的场景进程而非一句抽象梗概，但不设最低字数、固定场景数或固定剧情阶段；仅保留每条总计去空白字符不超过 300 的硬上限。

### Summary

### Suggested Action

在现有灵感界面加入单个“本章推进边界（可选）”输入，与 title／Bible／人物一起冻结到请求快照；双端继续只有显式生成按钮、等待、结果和失败。所有字数、节奏、人物与来源约束由后端程序复检和最多一次修复调用完成。
