## 共用错误与前后端契约

1. 错误说明统一由共享 Presenter 生成，明确“哪个动作／阶段、何种安全原因、下一步”。通知不打印正文、Prompt、密钥、原始 HTTP 响应、异常 repr 或被拒候选引证；旧页面和设置沿用现有通知详情／最近 30 条会话历史，不新建持久化全局通知系统。
2. HTTP 非成功错误在客户端保留状态码，以及现有结构化 `detail.code/message/details.names` 和 `detail.violations`。violations 使用现有安全形状 `code/message/names/current_chars`；畸形或未知字段安全降级为可读错误，不把原始 JSON/HTML 整段展示。后端现有响应格式保持兼容，旧字段不删。
3. `POST /chapters/{id}/check` 继续返回现有 `CheckerRunRead`；`checker_result.status = unavailable` 时添加可选 `error_message` 与 `error_context`。安全 context 复用现有白名单：`agent_role/model_name/http_status/upstream_reason/finish_reason/block_reason`；角色明确为 checker，模型来自实际调用客户端。旧响应缺字段可解码，未知异常只返回固定安全原因。
4. 手动 Checker 的错误上下文复用现有上游安全分类与净化规则，保留真实内容拦截／超时／限流／无效响应区别。记录一次真实调用的安全审计元信息（角色、模型、耗时、错误码及安全原因），不额外调用模型、不记录响应或正文；available/unavailable 均不能改变候选正文。
5. 重启恢复在覆盖 phase 之前，把已知原阶段加入 `error_context.interrupted_phase`，并填写相应 `agent_role`，保留其他已安全化 context。原阶段限定于服务端既有阶段枚举；客户端按明确原阶段优先映射，validating 必须显示程序校验，不能被 writer 角色盖成整章写作。缺失或未知阶段显示“任务中断／阶段未知”，不猜为 Writer。
6. 所有新增 DTO 字段为可选，加法兼容；如调整 Swift 内部 APIError 或状态枚举，更新现有 switch 与测试。`ChapterGenerationStage` 是已持久化的 Int 枚举，新增“接受正文”阶段不得改变旧 rawValue；老缓存缺字段使用保守默认。
7. 每次主动操作有独立身份。失败通知以 job ID、mutation ID 或该次请求 ID 去重：轮询重复／反复进入同一章不刷屏，用户再次发起同样操作后仍失败必须能产生新记录。通知只引用发起时的书章上下文，晚回包不得改写另一章；即便用户已离开，失败仍可在历史里找到。

## 9 项修复与恢复行为

### F1 接受失败不再误报成稿（P1）

- 分离“正在请求接受”与“服务端已接受、正在归档”。只有成功回包或后续权威章节读取确认 finalized，才展示已完成正文和归档恢复动作。
- 接受被 409／人物校验／配置等明确拒绝时，保留当前正文、草稿状态和安全原因，阶段为“接受正文”。不得切到“重试整理”或伪报成稿。
- Checker 失效／不可用时提供重新检查；人物问题指向本章人物／豁免修正；冲突沿用比较流程；修正后的接受仍走正常校验。既有显式忽略规则不扩张，人物正确性失败绝不自动忽略。
- 接受请求发生 transport 等不确定结果时，先只读核对章节与 job：若已 finalized 则采纳真实归档状态；若仍草稿则恢复可操作状态；若核对也失败，显示“接受结果暂未确认”并提供刷新状态。不得在确认前自动重复接受、取消后台任务或凭 catch 回退已接受正文。

### F2 双端成稿可查看并恢复归档失败（P1）

- iOS Reader 增加紧凑的归档待处理提示、完整原因和“重试整理”；Mac 使用相同共享状态与动作。正文与阅读导航继续可用，retry 只调用 `/archive/retry`，不重跑 Checker、不再次 accept、不改正文。
- 同时修正 `ChapterJobReconciler` 与 `ChapterTaskOutcomeStore.load`：finalized 只可保留与当前章节匹配的 extract 失败，不能一概清除；既往 write 失败、已完成归档、已失效 revision／本地输入不一致的旧失败不得复活。
- 以服务端 `outcome_current`、章节 archive 状态与匹配的本地快照为依据；旧服务未给可验证信息时保守显示当前归档待处理状态，不编造旧失败原因。重新进入／冷启动恢复失败记录到通知历史，复用现有不主动重复弹出的策略。
- retry 起动失败与运行中失败都保留成稿事实；成功后清除当前归档故障提示，但保留通知历史。

### F3 同步失败可见且保留本机内容（P2）

- 为 pending mutation 保存可兼容解码的安全失败状态（错误码、HTTP 状态、可读原因）；持久化在既有本地队列，不引入服务端数据迁移。失败项仍计入未同步，双端不再只显示“待同步”或用在线状态掩盖失败。
- 现有同步详情展示资源位置、原因、可用操作；提供明确重试，修改资源后允许用新内容再次提交。404 说明远端资源已删除并继续保留本机内容；不得为了清空红点自动丢弃唯一待提交值。
- 保持同一资源的原始 revision 基线与写入顺序。永久拒绝挂起该资源；无依赖的其他资源继续 flush，不能让单个坏项永久堵住所有修改。认证／全局配置错误停止本次 flush 并提示修复连接；transport 保留离线恢复语义；write_conflict 继续原有三方冲突流程。
- 自动 flush 不无限重发已挂起的永久错误；明确“重试同步”、连接修正或该项新编辑才重试。失败重试若仍拒绝须保留原因，成功才移除 pending 与该项错误。通知按该次失败去重，冷启动仍可从持久化详情看原因。
- 本轮不扩张批量丢弃／重排队列功能，不增加默认删除本机副本的恢复捷径。

### F4 手动复查 unavailable 必须说明真实原因（P2）

- 服务端按上述加法错误契约返回、记录审计。客户端即使收到 HTTP 200，也将 unavailable 作为检查失败展示具体原因并写入通知，页面提供再次检查入口。
- 不把 unavailable 记作有效检查结论，不允许它解除接受门禁。旧 concrete 检查只能作为失效历史保留；请求期间编辑过正文／切章的回包不得标记当前稿已检查。

### F5 手动预检保留逐项规则（P2）

- APIClient 解析 violations，Presenter 与错误详情展示当前字符数、字数门槛或人物未选／重名等实际返回原因，不只剩“确定性校验失败”。不重复泛化成模型错误，也不发模型请求。
- 覆盖 accept 同形状错误，避免只修 `/check`；仍区分作者短稿可显式忽略与人物失败不可忽略。

### F6 轮询错误保留“任务状态未知”事实（P2）

- transport、限流和可重试 5xx 可继续只读轮询并退避，显示真实原因与“尚未拿到最新状态”；重复错误不重复通知。401/403、404、确定性 4xx、解码不兼容停止自动轮询，给出实际原因及“刷新任务状态”入口。
- 停止轮询不等于后台任务失败：保留最后已知阶段，独立表示监测受阻；不得伪造 failed、解锁重复写作／重复归档或取消生产任务。
- 用户修正连接后刷新时，只 GET job／chapter；拿到权威状态后恢复正常轮询或终态，再允许对应业务动作。切章／离开时取消本地监测任务，晚回包受 chapter/job 身份保护。

### F7 服务重启保留中断环节（P2）

- 在 selecting_memory、writing、validating、checking、extracting 等原阶段分别保存安全上下文后执行既有恢复；不改变恢复后的正文、归档激活或所有权规则。
- 不完整／失效归档仍不进入有效记忆，旧任务不重新运行。前端显示确切阶段与服务重启原因；不认识的旧阶段诚实显示未知。

### F8 灵感错误进入全局历史（P2）

- 保留现有局部 errorMessage，同时给本次请求失败发布书章定位和安全完整原因；面板关闭后失败仍通知，切章后仅旧请求的通知可出现，不把错误覆盖到新章局部状态。
- 主动取消不伪报模型失败；每次明确生成按钮才发请求，打开面板不读取历史、不调用模型，成功卡片校验合同不变。

### F9 首次连接按真实结果提示（P2）

- `BookshelfStore.load` 显式返回请求是否成功；缓存填充、无 Token 跳过或内部 catch 不能算成功。iOS 连接动作只在书架远端请求成功时显示已连接／空书架引导。
- 401、transport、格式错误等保留原错误通知，已缓存书架继续可读。成功空书架与失败空缓存分别覆盖；Mac 和其他 load 调用点不能重新用空数组推断连接成功。

## 风险、回滚与资源

- 最大风险是把“不知道是否成功”当作失败，或恢复旧归档错误后允许重复写入。以只读权威刷新、明确任务身份、成稿状态和 archive 新鲜度控制恢复；通知展示不能改变数据生命周期。
- 队列修复不得重排同资源写入、抹掉 revision 基线或在持久化失败后声称安全保存。通知内容禁止顺手展示 raw payload，模型错误安全分类不可放宽。
- 保留 macOS 27 的具体 TextEditor accessibilityLabel 修复；双端页面改动须实际运行，尤其成稿页／编辑页及原因弹窗。
- 本轮无生产改动和数据库迁移；有必要回退实现时仅反向撤销本轮提交/明确改动，保留用户修改与本机原始内容。若随后获发布授权，按 Backend-first 既有一条龙规程另行执行，不复用旧 Build 标签。
- 测试前登记归属与产物；主会话最终核对本机任务目录、系统临时目录及后台进程，无远端测试目录则如实记录。将必要验证摘要写入本记录，失败现场仅保留代表性证据并写回收条件。
- 清理用精确清单及内容哈希确认，先停止本轮服务／测试进程、检查占用，再删已闭环临时库、虚构回复、日志和被替代构建；保留源码回归与必要证据。记录清理前后字节数和保留原因，禁止泛清共享 Xcode 缓存。
- Apple 构建收尾按全局规则运行设备支持审计，将 `pending_devices` 如实纳入交付；不因本轮故障验收增加模拟器或重置设备配对。
