## 产品决定与不变量

1. 把“正文有具体问题”“检查服务暂时不能给出可靠结论”“历史资料不完整”分开。格式坏、无证据和超时不能伪装成正文违规，也不能直接变成通过。
2. 保持候选仅在后端、人物选择是权限上限、真实未授权人物不可由通用忽略放行、Writer 正常产出至少4000去空白字且正常结束。作者短稿可先检查内容，接受长度不足仍必须显式确认。
3. 正文接受先独立落库；任何归档配置或运行失败都只影响记忆。归档每个 revision 仍只调用一次 Extractor；用户重试创建新 revision，可带上此前失败诊断，不做隐藏循环。
4. 归档采用下文 `archive-v2.1`：完整验证的是“叙事事实 + 可用状态 + 显式未知槽”这一原子包。旧 partial/failed/stale 不会因此生效。未知槽遮蔽旧投影，不能删掉出错项后继续冒充旧状态仍然确定。
5. 不以文字不同证明语义矛盾，不按证据句号或数组顺序推断故事时间，不自动取最后项，也不新加语义裁判模型。相同项机械归并；无法安全归并的状态保留问题定位和未知标记。
6. 历史不足允许作者明确知情后继续；不新增“一章归档失败就全书停产”的永久门禁。批量重提与自动修复真实历史不在本轮。
7. 用户已定的三句创作边界原文保留；仅增补检查证据、人物授权和输出协议，不改写其立场：
   > 为完成本章意图，可自然补充互动、场景衔接、局部波折、情绪与态度变化，以及已有关系中的渐进发展。
   > 只报告有证据的实质矛盾、核心要求遗漏、违背明确禁止事项或指定顺序与结局，以及未经授权的重大转折。
   > 没有上述具体证据时，不得仅因发挥较多而判为 suspect 或 violation；没有其他问题应返回 passed。

## 一、检查输入、事务与任务所有权（C7、C8、M4）

建立共享的不可变检查/写作输入快照及来源清单，供自动 Writer→Checker、手动检查、检查有效性、同稿重查共同使用。可新增窄服务模块，不再在多个调用处各自近似拼指纹。

- 快照包含正文哈希（生成前为空，候选形成后补上）、标题/Bible、世界观、已选人物稳定ID/姓名/固定卡、规范化豁免集合、真实章前状态及未知槽、实际送入的历史资料/来源ID/内容哈希、上一章结尾、程序检查协议版本。自动流程还保存 Selector 实际看到的候选范围摘要，覆盖新增或替换候选会改变选择的情况。
- Writer 和自动 Checker 使用同一个冻结 reference_context。手动 Checker 使用当前确定性组装的同类型快照，不额外调用 Selector。判定有效性复核来源及当前组装输入；不能拿全书“最新动态状态”代替本章章前状态。
- 来源的语义身份与内容哈希是有效性依据，revision ID 用于追踪。相同内容重新归档不必仅因新ID让检查失效；前章实际资料变化必须失效，后章变化不得使早章无故失效。旧检查缺少新契约快照时显示过期、可重查，不推定有效，也不删除记录。
- 所有模型等待在数据库事务外。手动 `/check`：短事务冻结输入并登记尝试→提交/释放 Session 事务→模型调用→新短事务重读并 CAS（比较后更新）保存。不能在网络等待期间 flush candidate 后悬挂写事务，也不持有长读事务。
- 落地检查结果和提升 Writer 正文均复核章节内容/任务代次及来源当前性。输入变动后只留下“已过期”尝试，不能覆盖新正文/新检查。两个手动检查乱序返回时旧尝试不得覆盖较新的尝试；客户端也按尝试ID/输入身份拒绝旧响应。
- 归档激活/失效/正文改动/人物及世界观变动都触达真实依赖失效。最终提交前的复核是正确性门禁；线程取消只作优化。不能继续只按 delta 中人物ID撤销后续写作。
- 接受的通过结论和显式忽略也绑定同一实际输入身份。前章资料改变后，旧通过/旧忽略不能直接继承。

验收：用暂停的假 Checker 实测另一章 PATCH 可及时成功；检查途中改正文/Bible/人物/前章事实均不能落旧结果；前章仅换 summary/facts、无 delta 的在途 Writer 不能提升；后章状态改变不使早章结论失效。测试应断言实际 API/数据库结果，不只查源码字符串。

## 二、Checker 结论与人物授权（C1、C2、C3、C4、C6、C9）

### 证据协议

- Checker 内部 issue 继续保留 `kind/reason/draft_evidence/bible_evidence` 兼容字段，新增 `source_kind/source_id/source_evidence`，指向冻结来源目录（bible/world/character/prior_state/history/draft/authorization）。来源ID由程序提供，模型不可自创。
- 引用必须在对应冻结文本中可核实。只做确定性换行/空白规范化，不用模糊语义匹配接受假引文；引用范围不能用省略号拼接冒充连续原文。正文内部矛盾用另一段正文作为 source；非Bible问题不再要求 Bible 引文。`bible_evidence` 仅镜像真实 Bible 证据，其他类型可为空。
- 核心要求遗漏是“缺失”而非已有正文片段：允许该类型正文引文为空，但必须有非空 Bible 明确要求引文和遗漏说明，并绑定整份已检查正文。空 Bible 禁止该类型，继续保留既有空Bible跳过规则。程序不宣称能机械证明语义遗漏。
- `passed` 仅能配空 issues；`suspect/violation` 必须有至少一条完整有效问题。不一致结果、伪造引文、未解析来源或必填证据缺失视为 `checker_invalid_response` / unavailable，不能静默删坏 issue 再 passed，也不能生成空 suspect。
- 公开拒绝候选仍仅出 `kind/reason`；新增源引文同样必须被删掉。只有属于当前可见正文的结论可展示完整证据。通用日志不记候选、Prompt、正文或上游原包。

### 人物识别与豁免

- 子串扫描只能产生“待辨别姓名命中”，不能把普通词直接认作出场。保留最长匹配/NFKC等规范化，去掉其直接等价于确定性违规的路径。
- 同一 Checker 调用补充待辨别人名的 `name_uses`：每个程序生成命中ID，返回 `character / ordinary_word / uncertain`、对应精确正文或Bible片段及理由。程序核实命中ID和引文归属；不能接受遗漏待辨别项的“全部通过”。已选角色与豁免先扣除，再做未授权/重名判定。
- 普通词判定通过后，“今年夏天天气很热”“窗外白雪皑皑”“林业改革”可正常检查与接受；作为人物说话/行动的未选夏天仍不允许。角色授权由程序提供的已选ID+明确豁免定义，模型只能辨别词义，不能授权。
- `uncertain` 是需要用户澄清身份/选择/豁免的明确问题，不能假报确定出场。未确认姓名的稿件可重查或使用具体姓名豁免，通用“忽略 Checker”不得跳过未解决的身份判断；没有姓名风险的普通稿件保留通用显式忽略。
- 同名时恰好一个相关ID已选可确定授权范围；多个同名角色实际需归属而无法区分时返回具体冲突。规范化姓名豁免在歧义分支之前生效。豁免仅允许提及该名字，不替 Extractor 创建人物ID或授权关联状态；确需状态归属仍须选择唯一人物。
- Writer/Checker 固定协议和实际上下文都包含同一已选/豁免授权表，检查指纹也包含它。当前双端给出具体的选择人物/添加姓名豁免入口及保存反馈，不假定旧UI入口已接入。

### 检查与接受

- `/check` 允许任意非空作者正文进入内容检查，不因4000字要求拦下；空正文仍拒绝。Writer 长度/截断门禁继续原样执行。
- 所有新导入、手贴或生成稿 `/accept` 均需当前可靠 passed 或本次明确忽略；删除“没有 candidate 即历史兼容稿”的推断。已 finalized 章节的读取不补跑 Checker；单独归档重试也不检查正文。
- 长度确认与 Checker 忽略分离：请求增加 `allow_short_draft`，不足4000即使 Checker passed 仍需其为 true。旧客户端的 `override_checker=true` 可作为一次明确短稿确认兼容；不得由历史存储的 override 自动确认新短稿。真正未授权人物和身份未解始终不能用这些通用参数放行。

验收：passed带issue、suspect空数组、假引文、历史证据/Bible为空、遗漏型证据、三类普通词及真实出场、同名豁免、修改豁免后旧检查失效；短稿先检查后接受必须独立确认；无candidate新导入直接accept应409，显式忽略的合规稿可接受。

## 三、同一候选后台重查（C5）

增加 `POST /chapters/{id}/checker/retry`，请求只含公开 `source_job_id`，返回既有 `WriteJobStatus`。这是重试最近失败任务的动作，不是候选选择接口。

- 仅最近一次因 Checker 不可用/无效输出失败、且已通过 Writer 确定性门禁的未提升候选可恢复；服务端自行定位候选。正文被改、输入快照过期、已有新写作/接受/重开、后续尝试取代时返回409及准确理由。
- 新尝试在后台重用不可变正文与冻结 Checker 输入，Writer/Selector调用次数为0；通过时仍走同一最终所有权/当前性原子提升逻辑。失败仍保留旧可见正文；不提供无效/违规候选的接受或正文预览接口。
- 新 JobRun 持久关联原job/候选，处理重启恢复和重复点击；不依赖进程内对象可恢复。一次点击只调用一次 Checker，不自动循环。进程重启后能力可正确显示或明确失效。
- 状态增加 `can_retry_checker` 与来源任务ID；UI文案为“重新检查这次生成”，显示正在检查，不能错连旧正文 `/check` 或再次 `/write`。

验收：Writer一次、Checker失败后重查成功并提升；输入变化拒绝重试；跨端/冷启动恢复；候选正文及所有证据不出网；较晚任务不能被旧重查覆盖。

## 四、Selector 与降级上下文（M1、M2、M3、A6）

- 没有可选择的历史事实时跳过 Selector 配置解析和调用；若只有上一章结尾，确定性保留有界结尾即可。不能因为一个完全不用的角色配置错误挡住首章。
- 统一预算：简报与冲突合计最多2400去空白字，紧邻上一章结尾独立最多700字；现有条数/来源数上限继续有效。提示、Agent解析、打包、实际Writer/Checker输入按同一规则。700+1800用例不能丢简报。
- 对每条text/source_ids、来源是否属于本次候选、结尾ID、字数及限额作完整校验。沿用 Selector 最多两次总调用的校正机会；第一次输出无效给具体原因，第二次仍无效返回明确选择器故障，不静默删成“没有相关历史”。合法的主动空选择允许；禁止增加第三次重试或隐藏降级。
- 已验证 conflicts 连同具体来源进入 Writer/Checker 的共同上下文和安全公开记忆说明，作为待核对的历史事实，不赋予它们覆盖本章Bible的权限。模型不能仅凭冲突条目存在就拒绝正文；仍按已定边界与可核实证据判断。
- 增加只读 `GET /chapters/{id}/production-readiness`，返回 `context_token`、缺失/部分状态/沿用旧记忆的历史章节（ID/章号/标题/原因）及建议先恢复的章节。它与真实快照/投影用同一个服务，不复制另一套状态判定。
- `/write`、`/check` 增加可选 `acknowledged_context_token`。存在缺失/不确定历史时，新UI先显示“一次写作将缺少哪些资料”，可去恢复或明确继续；未经确认返回409 `memory_context_incomplete` 附当前token/缺口。token过期需刷新，不能用永久布尔绕过。无缺口无需此流程。
- 确认后任务和 Checker 结论持久携带 `context_limitations`；“通过”只表示已提供资料范围内通过。任意新发现的坏 Selector 输出不属于用户此前确认的历史缺口，仍作为故障处理。
- 只读 readiness 可在工作台载入/生成动作前读取；不引入自动模型调用。灵感既有“明确按钮才请求”规则不变；若消费同一历史服务，也必须排除无效revision并带必要的缺口说明。

验收：无历史且Selector未配置仍正常Writer；有效conflict真实进入两个模型输入；未知source ID不被静默吞掉；缺失历史的API与双端知情继续/先恢复/输入变化后重新提示走通。

## 六、archive-v2.1 的局部状态缺口（A2）

这是有意修改旧 all-or-nothing 契约，builder 必须同步根AGENTS相应铁律，不能让代码与旧规则相互矛盾。

### 验证与原子激活单元

- 保持存储 `schema_version=2`，新增 `contract_version=archive-v2.1`。一个可激活包必须完整具备：有效summary、所有canonical facts均有效、已验证且无歧义的delta集合、完整可定位的uncertainties集合、受控diagnostics。整包一次原子激活，DB revision仍只能complete时active。
- 顶层结构、summary/facts、未知人物/坏来源/无法安全归属的输入错误仍使整包partial/failed；不能从任意坏输出捞几条事实生效。无需扩大此次修复成通用容错解析器。
- 仅已通过身份/归属/来源验证、能精确确定规范槽位的状态局部错误可隔离：同槽不同operation/value、槽值整体占位、该槽值类型/长度无效。相同槽的所有争议delta都不落有效state表，写一条uncertainty；其余有效facts/delta正常入包。字符串不同只叫“同一状态槽有多个不同结果，尚无法确定”，不叫正文实质矛盾。
- uncertainty键为人物+scope+slot+可选关系对；归属依据必须有效，保存code与相关fact_ref/span。不使用set/clear冒充未知；它是独立投影遮蔽事件，不是小说中发生了“清空状态”。
- 投影按章节顺序同时回放有效delta与uncertainty。遇未知槽移除先前确定值并标记未知，不能回退到更早值；后续有可靠set/clear才解除该槽未知。关系按无向人物对处理，两侧一致。当前人物卡、章前状态、Selector/Writer/Checker/Extractor、记忆导出及故事线都保持这一语义。
- facts仍可叙述发生过的事件，不能自动从这些facts反推出争议槽的最终状态；参考上下文明示未知槽与来源章。不确定状态不得编成确定人物动态值。
- 重试成功用新完整包替换该章旧包，清理旧uncertainty投影；重试失败保留此前有效包。相同正文内不能混合两个revision的facts与state，以免制造拼装事实。

### 持久化与兼容

- revision添加JSON `diagnostics`、`state_uncertainties`（默认[]）及必要的私有输入/检查快照字段；具体归置由集成owner按职责选candidate/JobRun，不放公共记忆字段偷渡候选。新增一条顺接 `20260830_0013` 的Alembic迁移，ORM/默认值/约束与迁移一致。
- `archive_input_fingerprint` 必须接受契约版本并按被验证revision自身版本计算。旧 `archive-v2.0` 的历史hash算法保持兼容；不能只替换全局常量让所有旧complete失效。v2.1输入包括未知状态语义。旧完整归档无输入变化原样可用；旧partial仍不生效，不触发自动模型。
- 当前可用记忆与最新尝试分开返回。新 `effective_status = full / with_state_gaps / none`、`state_uncertainties`、`diagnostics`、`latest_attempt`（status/code/message/time）明确表示真实结果。旧 `status` 在有状态缺口时投影为 `partial`，使旧UI仍提示需留意；这是显示聚合状态，不是把DB partial revision放行。新UI据effective_status说明“摘要与事实可用，部分人物状态待整理”。

## 七、归档恢复与双端可见性（A6、A7、A8）

- 归档详情、章节轨、书籍健康统计同时表达effective memory及latest attempt；“旧记忆仍可用，但本次更新失败”必须持续可见，不只依赖即时toast。拥有active包的失败尝试也计入attention；未知槽亦计入attention。聚合查询保持有界，不每章重复查全书。
- `production-readiness` 提供建议首先恢复的前章及依赖原因。通常按受影响章节的阅读顺序恢复；无共享状态/无实际依赖的章节不假报阻塞。点击更后章重试前返回 `archive_prior_recovery_recommended` 附前章ID、当前token；用户可跳转前章，或本次确认仍重试。`ArchiveRetryRequest.acknowledged_context_token` 用来承载该确认。
- 前章恢复会让依赖它的后章旧状态过期时，前端刷新受影响章并通知，不隐藏已完成任务的失效；重试不能自动扩大到全书。维护模式 selective_reextract 的报告/hash/精确ID规则原样保留。
- 新错误/提示接入两端现有通知历史与安全错误呈现；正文接受、有效记忆、最近尝试、检查服务不可用、当前正文问题各有准确文案与动作。不把“重试检查”“重新写作”“重试整理”互相错连。
- Additive wire字段均提供默认值，旧缓存解码安全；新App连旧后端时新入口按能力/404降级为明确说明，不能悄悄执行不同动作。旧API仍能阅读、接受正常已检查稿和重试归档；涉及新增知情确认时旧客户端得到可诊断409，不能静默漏过新门禁。

验收：成稿归档启动失败、完整失败、带状态缺口成功、旧记忆仍有效但最新失败、逆序恢复警告、后章继续前知情确认、Checker同稿重查及过期结论，在真实HTTP+Store与隔离双端页面可区分并可恢复。

## 版本记录

### v2.0.4 / v1.9.5（Build 46）

- 恢复两个在 v2 clean-room 重写时丢失的章节能力。「重写本章」保留作者写给 Agent 的输入——本章意图、标题、出场人物、豁免名单与备注——只推倒 Agent 产出的正文与归档；「删除本章」连同作者输入一起抹掉整章。此前成稿章既无法重新生成也无法删除，唯一出路是手工清空正文。
- 「重写本章」不设最后一章限制，改为在确认框里列出会被作废归档的具体章号——因为重开后手改正文本来就能造成同样的级联，且一直不设防；「删除本章」只允许全书最后一章，由服务端强制。重写期间旧正文仍要等新稿双双通过校验才被替换，失败则原样保留。
- 一并修掉删除路径两处既有缺陷：注定被拒的请求不再先杀掉正在跑的生成；后续章节的在途写作输入现在会被真正作废，而不是靠"闸门下不可达"的论证搪塞——那条论证已被实测推翻。
- 两端入口由同一份共享状态与同一份确认文案驱动，iOS 阅读器与工作台的重复实现已合并；新增门禁守卫锁住入口的存在与接线，防止再被无声丢掉。同时修正 iOS 章节菜单缺少文字标签造成的可发现性问题——那正是本轮起因。
- 本版不改数据库结构，无迁移。已部署宁波生产并通过发布验收；macOS 已换装并启动，iOS 安装由用户自行处理。
- ⚠ 本版未做端到端手动验收：新增的是破坏性动作，在生产库上试错等于真丢数据，补验需要隔离后端与测试数据。

### v2.0.3 / v1.9.4（Build 45）

- 本版来自一轮覆盖 Backend、双端客户端、测试与文档的全量审计，内容全部是修复与收口，不新增任何产品能力，也不改动数据库结构。
- 客户端不再有"看起来成功、实际没保存"的路径：iOS 章节工作台与各面板现在都会显示保存失败；服务器回包不再覆盖往返期间输入的文字；打开某个 Agent 的人格页不会再清空它的推理配置；macOS 新增人物失败不再改写既有人物的固定设定，世界观与新建书保存失败也不再关闭面板丢弃输入。
- 归档口径收口：一次失败的归档尝试只作废它自己，不再连带剥夺章节自身的记忆来源；人物详情页与记忆导出统一为每章单一来源。
- 后端暴露面收口：关闭 CORS 通配与未鉴权可读的接口文档；`/health` 改为实际查库并比对本版期望的 Alembic head，使它能真正作为发布闸门；占位密钥拒绝启动；更换模型服务地址必须同时重填密钥；密钥无法解密、畸形地址和显式 null 由 500 改为可诊断的明确错误。
- 合同收口两项：`accept` 不再因为章节从未产生过候选就跳过确定性校验——未选／重名人物一律拒绝且不可忽略，长度不足可由作者显式忽略后接受；被拒候选的逐字引证不再随任务状态出网，只保留结论类型与理由，后端留档不变。两项均已写入铁律。
- 门禁本身也是本版的修复对象：客户端回归脚本此前在检索工具缺失时会把守卫判成"通过"，且指向已不再构建的旧文件；改为工具失败即失败并指向现行界面后，第一次真正跑完。另新增 ORM 与 Alembic head 的结构一致性守卫，实测当前无漂移。
- 双端 Release 构建、签名、ZIP 解包复核与 macOS 换装启动均已通过；macOS 改用标准 archive 流程出包，可执行体已 strip 并另存 dSYM。
- 本版已部署宁波生产并通过发布验收：零迁移，内外网鉴权健康返回 `1.9.4`，未鉴权 401，接口文档三个入口均已成为 404，单实例、数据库完整性、外键与零在途任务均通过，部署后 journal warning 为零；数据库内容未受部署影响。
