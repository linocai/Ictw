## 2. 关键技术决定

1. 新提取契约使用 `archive-v2.2`，沿用 ledger schema_version=2，同一次 Extractor 输出增加四类**事实引用索引**。只新增 revision 上一个 JSON 列，保留既有 facts / deltas / uncertainties，不增建摘要体系。
2. `production-input-v3` 增加紧邻上一章承接包，服务端从有效归档及已接受正文装配，独立于 Selector 和远历史2400字预算；Writer与自动Checker消费同一份冻结引用文本和来源目录。
3. 新 Selector 只选择更远历史的原文来源，服务端装配整条来源；删除新请求中自由改写事实和选择前章结尾的职责。保留已有五段链和合法重写复用，不增加调用。
4. 承接检查增加稳定 kind，沿用现有 source_kind、引证字段、判定/接受机制和双端结果入口；程序验证来源和引文，语义判断仍属于Checker。
5. 在双端现有 Writer / Checker 角色设置增加用户明确点击的“质量优先”预设，启用当前 Profile 支持的思考与 high；不换 provider/Profile，不自动更改全局或单书设置。

待用户决定事项：**无**。模型质量尚待用户判断是验收边界，不是阻塞施工的技术决策。

## 3. Extractor v2.2 与持久化

### 3.1 输出与归一化契约

在现有 `summary`、`facts`、`end_state_delta` 之外，新增必需对象：

```json
{
  "continuity": {
    "completed_fact_refs": ["F1"],
    "known_fact_refs": ["F2"],
    "last_landing_fact_refs": ["F3"],
    "open_fact_refs": ["F4"]
  }
}
```

- 四个数组必须存在，允许为空；每项必须引用**本次输出**中真实存在、已完整验证的 fact_ref。每数组去重后至多沿用 `MAX_FACTS=8`，总体引用只能落在已有canonical facts中；不新增事实额度、不复制事实文本或证据。不同类别可引用同一事实，渲染时事实只出现一次、附多个标签。
- `completed_fact_refs` 表示“本章已经发生的关键进展”，不把持续行动变成已经结束、把决定变成已经执行，不能指向“未决”类事实；分类不能增强原句的确定性。
- `known_fact_refs` 只引用“认知”类事实。认知主体以事实原句及参与者为准，不能把参与者名单机械解释为人人均已知；无法明确主体则不分类，事实仍保留。
- `last_landing_fact_refs` 指向正文结束时仍成立的最后落点或策略等事实；`open_fact_refs` 只引用“未决”类事实。不能按事实数组位置、源句在后或非线性叙事顺序猜章末时间或状态。
- 复用原 fact 的 start_id/end_id 来源定位。对模型临时 fact_ref 的别名去重/机械重编号必须同步重绑定四个数组；归一化后仅保存 canonical fact_ref。未知引用、类型错误、额外字段、不合法分类均按当前归档协议失败路径返回，不能偷偷丢弃坏引用后激活。
- 新合同只有 `summary + canonical facts + deltas + 程序生成的uncertainties + continuity` 整体校验后才能原子激活。失败不能撤销章节接受、损坏旧活跃revision、重跑Checker或再调用Extractor。未能归类不等于提取失败：空数组合法，结尾原文仍提供落点。
- Extractor保持120秒硬限、8192输出token、固定非思考，以及每revision最多一次模型调用；不提高事实/摘要数量与篇幅上限。v2.0与v2.1按各自合同验证、构建schema和fingerprint，不能让最新常量改变旧revision的判断。

## 4. 紧邻上一章承接包

### 4.1 选择与降级

- “上一章”仅指**同书 index = 当前index−1**，不取最近一条finalized记录跨过缺章。首章自然没有；缺章、未接受、重新打开中的前章都不提供事实或正文，不从其旧归档、旧候选补回。
- 前章finalized且活跃revision有效：v2.2取完整summary、全部≤8条canonical facts、continuity与已有状态不确定性；v2.0/v2.1直接取完整summary/facts，标注“旧归档无承接分类”，不调用模型、不猜分类。
- 没有有效v2时，仅在`legacy_archive_eligible`且现有legacy判定有效时使用该章唯一legacy来源，继续原摘要/事实/未决事项。不能同时混用失效v2和legacy。legacy没有分类不构成必须重提。
- 前章已接受但归档尚未有效：不读partial/failed/stale归档事实；仅当当前保存正文仍属于该次finalized接受状态且校验没有失效时，可提供**已接受结尾原文**，标为`ending_only`并沿用“缺少有效记忆”的readiness提醒。不能把正在修改的草稿或不再匹配接受状态的文本当作这个来源。
- 前章结尾由程序固定选择当前既有700个去空白字符上限内的尾部文本，不让Selector删选；尽量保留自然句/段落，只取完整句段。单一超长句若无法在既有上限内完整容纳，则不截成残句，明确结尾不可用并记录限制。引用有效归档与已接受结尾是不同来源，不把“只有结尾”描述为完整承接。
- 资料带来源章ID/index、source模式、contract版本、原始来源ID、语义身份和内容hash；用于溯源的revision数据库ID不充当语义身份。保留姓名及完整多人参与者身份，历史不授权当前章未选人物；未决/待定也不能作为“相反事实”或强制补写理由。

### 4.2 长度、渲染与公开面

- 独立承接区使用已有数据合同推导的界限：summary最多4000 + 最多8×500事实 + 最多700结尾，共至多8700个正文字符，标签/引用只作有界元数据。**不是抬高单项限制**，而是让上一章既有有效信息不被远历史预算挤掉；v2资料不经自由压缩、任意截断或选择性丢弃。
- legacy超出可容纳范围时先保留完整摘要，再按现有稳定来源顺序装配整条事实，放不下整条就略过该条并继续尝试后条；不拼接残句，不提高上限。readiness及manifest明确记录legacy资料有省略，沿用知情继续路径；实际进入上下文的整条来源才进catalog。
- 统一章节渲染区分：已发生起点／已知事实／最后落点／未决事项／无分类事实／已接受结尾。各事实只渲染一次，分类不重写事实。没有分类不填推断值，不要求作者手填新的表单。
- 冻结快照增加 `previous_chapter_context`，存上述机械构建的资料及真实限制；`source_catalog`仍用`history`，为每一条被传输的原始事实、摘要和结尾建可引用entry，不新增source_kind。自动Writer与Checker的`reference_context`字节一致。
- JobRun公开memory_context可增量提供 `previous_chapter_context` 的来源章、模式、实际资料及限制，沿用已有“历史资料”展示可选解码。只包含作者已有的已接受历史，严禁借此公开当前Writer候选、拒绝正文或候选引文；不要公开整个input_snapshot。
- 缺前章/归档失败等沿用现有readiness确认语义；首章和可用的旧归档无需新增确认。新增省略类提示使用现有列表，不做复杂配置；“超预算未采用”不可推荐无意义的重新归档。

## 5. 远历史 Selector：选择原文，不再改写

- 仅当前index−2及以前的有效单一记忆来源进入新Selector候选。紧邻前章与700字结尾由专用包接管，不能再通过conflicts或briefs复制回远历史区域。
- 新模型输出合同：`{"selected_source_ids":["M1"],"conflict_source_ids":["M2"]}`。只能复制本次候选别名，不返回自由文本、结尾起点、时间/因果推断。`selected_source_ids`至多沿用8条、`conflict_source_ids`至多沿用4条；同一ID不得重复或跨两数组出现。选择顺序仅表示相关性，不表达事件时序。
- 服务端将每个ID解析为整条已存来源原文，沿用公开 `memory_brief` / `conflicts` 的text/source_ids形状；text完全由程序取原文，不接受模型替代。冲突来源区说明“这些历史资料可能与Bible存在冲突，需核对”，模型不得写冲突解释；实际冲突由Writer/Checker对照原Bible与原来源判断。作者Bible优先及历史不授权规则不变。
- 保持现有远历史 `MEMORY_BUDGET_CHARS=2400`、候选300条/30000字筛选界限和相关性规则。去重后按最终实际原文计算总量；**被选整条合计超预算属于协议不通过**，使用原有至多一次纠正机会，仍超限则`memory_selection_invalid`，不悄悄裁切、不默默变成空历史、不启动Writer。
- 单条原文已超过2400，程序在Selector前确定性排除并记入readiness限制/来源章，说明“此历史条目超过当前原文预算，未用于本次参考”；不要求用模型重新提取。作者可沿用现有知情继续。未超限却仅因相关性未被选中不逐条报警。
- 没有远历史或合法选择为空时正常走Writer，不为零候选调用Selector；上一章专用包仍完整存在。保留既有调用上限与协议纠正次数，不新增纠错模型或语义重试。
- 手动Checker不调用Selector，使用同一上一章包，远历史按既有确定性相关性次序打包整条、遇到放不下条目跳过；冻结实际选入来源，并明确预算造成的范围限制。不要将自动选择与手动确定性选择冒充完全相同，但单次自动Writer/Checker必须相同。

## 6. 冻结身份、重写与旧任务

- 新写作与手动检查生成 `production-input-v3`，fingerprint包括上一章实际来源内容、分类、参与者集合、结尾、前章状态/位置、远历史候选语义范围、manifest及原有Bible/世界观/人物/未知槽依赖。
- 前章被重开、删除、改稿、改变接受状态、换到内容不同的归档，或新增前章改变了“无前章”状态，均使受影响在途输入失效。CAS失败不得提升候选，候选及JobRun终态原子规则不变。
- 同内容重归档只换revision/fact数据库ID，且分类、参与者、全部来源文字/顺序与未知状态相同，属于等价来源，可机械重绑定；改变已知/未决分类也算语义变化，不能只比较文本。
- 新重写复用key升级，包含v3/Selector合同版本、上一章语义资料和现有作者输入及Selector人格；用可证明的语义身份复用原选择，不能由于复用绕过新上一章包校验。选择/正文/Checker之间禁止临时重读并替换冻结资料。
- 新请求不复用v1/v2自由压缩manifest；第一次Build75新写作按v3重新选择一次，以后条件相同才复用。旧已存候选、manual check和只重试检查继续以自身v1/v2冻结合同验证当前性，不把它们临时升级成v3或补入今天的资料；只有原有真实依赖变化才按既有过期路径处理。
- 保留v1/v2专用candidate-range、旧previous_ending选择和fingerprint实现用于旧快照验真；不可让新全局`_history_blocks`筛选方式直接使旧结果一概过期。向旧候选说明的是它原来实际读到的资料，不声称已享有Build75承接检查。
- settings变化只影响后续请求，不能修改在途已冻结的prompt、模型客户端或历史结论；原有单书优先、空Bible、人物授权、用户编辑和跨会话任务所有权保护继续覆盖。

## 7. Writer与Checker的具体行为

### 7.1 Writer

更新默认可编辑指导与程序协议/最终请求契约：在内部区分“章前已经发生什么、谁已经知道什么、本章要求新增什么、作者要求怎样经过并到达结果”，只输出正文，不外显分析或新结构模板。

- 不把已有认知重写成首次发现，不把已完成的关键进展再次当同一新转折，不先完整兑现明确要求经过某过程后才发生的结果、随后又把同一结果写成转折。
- 已有熟悉感、试探与渐进迹象不等于完成关系跃迁；允许围绕本章意图的正常互动、回忆、重复工作/日常、呼应、递进与作者有意的倒叙/插叙。不能把所有重复词或相同行为判为重复推进。
- 作者明确指定的顺序、过程和终点优先；未指定时不机械套“起承转合”或固定场景数。历史事实冲突沿用原Bible优先策略与原样来源提示，不能静默重写历史来使两边一致。
- 空Bible继续跳过作者剧情要求比对，其他事实与人物授权规则照常。保留4000去空白字下限、无产品上限、长度/截断最多一次完整重写；本轮不以字数为根因改规则。
- 已存全局/单书可编辑人格（包括BibleFocus追加文本）原样保留；不要用seed/迁移追加新创作偏好覆盖用户文本。必要协议进入只读PROGRAM_PROTOCOLS并在设置中如实显示；默认人格只影响默认值与用户主动恢复默认。

### 7.2 Checker与接口

沿用现有issue字段和判定逻辑，新增kind及双端中文标签：

| kind | 展示 | 合法来源 | 判定边界 |
| --- | --- | --- | --- |
| `continuity_repeated_progress` | 重复推进 | history / draft | 同一关键完成或首次发现被再次当新进展；允许日常重复、明确回忆与呼应 |
| `continuity_known_reset` | 已知信息倒退 | history | 正文明确把有来源的已知写成不知或首次发现；不凭沉默或未提及推断遗忘 |
| `continuity_timeline_conflict` | 时间承接冲突 | history / draft | 已有明确时间关系被颠倒或凭空延长；不靠段落位置猜时间 |
| `required_order_conflict` | 指定顺序冲突 | bible | 作者明确过程/结果顺序被违反；不把未指定的过程强加为硬要求 |

- 每条仍需准确source_id/source_evidence与draft_evidence；source_evidence在冻结原始来源中逐字匹配，draft_evidence在当前待检查正文中匹配。kind对应source_kind矩阵由程序校验；非Bible问题的bible_evidence为空，顺序问题必须引非空Bible。不能引用Selector生成的解释、待定状态或不存在的承接分类作确凿事实。
- 本章内重复兑现同一结果可用`source_kind=draft`引首次兑现、draft_evidence引再次首次化的文字；缺少可引用矛盾证据则不得报告该kind。检测语义是否真重复仍需模型与作者判断，字符串验证不能证明语义正确。
- 无有效证据/错引文属于Checker协议失败，沿用已有错误与显式重试，不伪装成文章违规或passed。未知旧kind的解码/原文标签fallback保留，不扩大本轮到全量kind枚举迁移。
