# Handoff: ICTW v2.0.0 — 方向 1b「台面 / Desk」

## Overview

ICTW 是面向长篇小说创作的原生写作工具。本包是 v2.0.0 客户端（iOS + macOS）的 clean-room 设计交接：在只读后端能力合同与产品行为合同的前提下重新设计的前端，不参考任何旧版界面。

已选定方向：**1b「台面」**——把「这一章要发生什么」（本章意图 / Bible）和「这一章写成了什么」（正文）放在同一工作台上互相对照，AI 的每条结论都必须指着两侧的证据说话。方向探索文件里的 1a「手稿」与 1c「编年」为未采用备选，仅作背景参考。

核心产品判断（实现时的取舍依据）：

- 唯一的产物是作者拥有、由作者拍板的**正文**。竞争时的优先顺序：正文 › 本章意图 › 本章相关人物与记忆 › 全书设定 › 模型设置 › 诊断。
- 作者只感知**三个动作**（生成这一章 / 复查这一章 / 接受这一章）、**一个后台事实**（接受后自动整理记忆）、**一个侧挂能力**（找方向）。五个 Agent 的角色名（Writer / Checker / Extractor / Memory Selector / 灵感创造师）只出现在设置界面与「依据」展开层，正常流程中一律不出现。
- 目标作者是「边写边想」，因此右栏（意图栏）**默认收起**为 44px 竖排轨，仅在没有意图、或产生了新结论时自动展开。

## About the Design Files

本包中的 `.dc.html` 文件是**设计参考**，用 HTML 表达的静态高保真原型，展示预期的视觉与行为，**不是可直接复制的生产代码**。

任务是把这些设计在目标代码库的既有环境中**重建**：ICTW v2 的目标是原生 iOS 与 macOS 客户端，因此实现语言为 **SwiftUI**（macOS 单窗口三栏 + iOS 导航栈），沿用该 codebase 已有的模块划分、状态管理与命名约定。HTML 只用于表达布局、层级、状态语义与文案，不要移植其 DOM 结构或 CSS 类。

打开方式：`.dc.html` 可直接在浏览器打开（同目录需保留 `support.js`）。文件是横向/纵向平铺的帧板，可自由缩放平移。

## Fidelity

**High-fidelity（hifi）。** 颜色、字号、行高、间距、圆角、状态色均为最终值，可按本文档的 Design Tokens 逐项对齐。唯一不是最终值的是插图性内容（示例小说正文、人名、章节名）与 macOS 窗口装饰（红黄绿灯为占位，实际由系统绘制）。

原型**不含交互**：每一帧代表一个状态，状态之间的迁移见「Interactions & Behavior」。

两个平台共 46 帧（各 23 帧），一一对应，编号相同：A 主路径 6 帧、B 失败与取消 3 帧、D 重开与失效 3 帧、E 周边页面 6 帧、F 人物与起步与深色 5 帧。

### A · 主路径（6 帧）

**A1 新的一章。** 正文区空态：灰色章节标题 + 待填写的标题下划线 + 「还没有正文」+ 闪烁光标；**不出现任何"暂无内容"式提示**。意图栏展开，含三块：本章意图输入框（`#FFFDF8`，`1px rgba(27,25,23,.12)`，radius 7px，min-height 132px，宋体 12.5px/1.85，**无占位说明文字**）、其下「✦ 找方向」按钮、本章出场人物 chips（选中为深底，未选为描边，`＋` 为虚线描边）。主动作：「生成这一章 ⌘↩」。复查与接受为不可用态。

**A2 生成中。** 意图栏自动收起为竖排轨；任务带出现（`#F6EEE0` / 边框 `rgba(160,113,58,.28)` / 圆点 `#A0713A` 呼吸），文案「正在写这一章」，右端「取消」（`#A6392B` 描边）。正文保持原样且**仍可编辑**。动作条主按钮在 iOS 上改写为「取消生成」。

**A3 正文生成完成。** 任务带转为 `#F2EFE4` / 边框 `rgba(74,107,82,.3)` / 圆点 `#4A6B52`，文案「正文已更新 · 检查通过 · 5,140 字」。Writer 的新正文只有在确定性校验与 Checker 都通过、且任务仍持有本章所有权时，才会与任务终态一起原子替换当前正文；客户端不展示待采用候选、候选全文、采用、丢弃或候选差异。意图栏自动切到「证据」档，并只陈述当前正文可证明的结论。

**A4 改动正文后，结论失效。** 证据档顶部出现斜纹条（`repeating-linear-gradient(45deg,#EDE8DE 0 5px,#F2EDE3 5px 10px)`）+ 一行「正文已改，以下结论已失效」；原结论卡整块保留但 `opacity:.5; filter:grayscale(1)`——**失效只降级，不清除**。主动作改写为「重新复查 ⌘R」。正文中被改动的句子以 `rgba(160,113,58,.16)` 底 + 1.5px `#A0713A` 下划线标出。

**A5 复查通过。** 章节轨状态点变为 1.5px `#4A6B52` 空心圈；证据档标签下划线转 `#4A6B52`；只显示「检查通过 · 对应当前正文」以及 Checker 实际返回的证据，不虚构固定检查项或通过卡片。主动作变为「接受这一章 ⌘⇧A」。通过态**不做庆祝动效**。

**A6 已接受。** 正文栏背景转 `#FBF8F1`，正文颜色降为 `#57514A`（只读），标题旁「已接受」徽标（11px `#4A6B52`，边框 `rgba(74,107,82,.35)`，radius 4px）。正文末尾虚线分隔后出现「开始第十五章」。意图栏第三档变为「这一章留下的」：顶部「正在整理这一章的记忆」（`#A0713A` 呼吸点），下方逐条长出关键事实 / 人物状态变化卡（标注来源章节），未完成的一条为虚线占位卡。**「正文已完成」与「记忆归档」是两件事**：归档失败不影响完成状态。底部动作条：重开这一章 / 导出。

### B · 取消与失败（3 帧）

**B1 取消。** 任务带转中性（`#F1EDE6`，空心灰圈）「已取消」+「重新生成」。取消不弹确认。正文位置与内容完全不动。

**B2 生成失败。** 任务带 `#F7EBE7` / 边框 `rgba(166,57,43,.28)` / 圆点 `#A6392B`，文案「没能写出这一章，正文没有变化」，两个动作：改意图再试 / 重试（主）。章节轨该行状态点转 `#A6392B`，左边框转 `#A6392B`。**不出现任何错误码或机器信息。**

**B3 四种失败。** 四张横幅组件，句式固定为「发生了什么 → 你的正文怎么样」，动作按环节区分：

| 情形 | 配色 | 文案 | 动作 |
| --- | --- | --- | --- |
| 未配模型 | 红 `#F7EBE7` / `#A6392B` | 还没有可用的模型 | 去设置 |
| 写作失败 | 红 | 没能写出这一章，正文没有变化 | 重试 / 改意图再试 |
| 检查不可用 | 琥珀 `#F6F1E4` / `#C08A2E` | 这次没能检查 | 再检查一次 / 仍然接受 |
| 归档失败 | 琥珀 | 记忆没能整理，这一章仍然是完成的 | 重试整理 |

### D · 重开与失效（3 帧）

**D1 重开确认。** macOS 为居中模态（452px，radius 12px，阴影 `0 20px 50px rgba(27,25,23,.28)`，背后正文 `blur(1.5px) opacity(.55)`）；iOS 为底部弹层，主按钮 `#A6392B`。用**具体后果**代替「此操作不可撤销」：正文与本章意图保留（实心点）· 第 13、14 章的记忆失效（斜纹方块）。确认层出现的同时，章节轨中将被波及的章节**已经染上斜纹**（自上而下 400ms）。

**D2 重开之后。** 被重开章节状态点转 1.5px `#A0713A` 空心圈，标题旁「已重开 · 草稿」徽标；下游章节整行斜纹底。意图栏第三档变为「受影响的记忆」，逐条列出失效事实（斜纹卡 + 「第 N 章 · 不再可靠」）。iOS 上此帧即**章节轨列表页**：整行斜纹 + 行尾「记忆失效」。

**D3 人物卡。** 两层结构：上层 `#FFFDF8` 纸白，是作者写的设定（身份 / 性格 / 底线），可编辑；下层 `#EFEAE0` 暗纸，是「整理自正文 · 只读」的归档条目，每条标注来源章节，失效条目打斜纹。这一分层是「我设定的」与「从正文整理出的」的唯一区分手段。

### E · 周边页面（6 帧）

**E1 书架。** 无封面无卡片，只有一列书名（宋体 17px）+ 章数 + 右侧状态（正在写第 N 章 / 相对时间 / 「N 章记忆待重整」斜纹标）。行高约 52px，行间 `1px rgba(27,25,23,.10)` 分隔。当前书：`#FFFDF8` 底 + 左 2px `#A0713A`。右上「新建一本 ⌘N」。

**E2 新建一本。** 书名（单行）+ 世界观（多行，可留空，占位「可以稍后再写」）+ 创建。iOS 版含软键盘态（键盘区 200px，键位为占位块）。

**E3 世界观。** 与正文同一版心（600px）的单一长文本编辑器。用户可在文本内自行书写标题与空行，但客户端不把它们保存成结构化分节，也不提供「新增一节」或排序能力。

**E4 找方向。** macOS 为正文栏底部升起的半屏（`border-radius:14px 14px 0 0`，阴影 `0 -14px 40px`），三张候选横向并排；iOS 为底部弹层，三张纵向堆叠。每张：宋体 13.5–14.5px 建议文本 + 「用这个」。顶部「换三个」。**零副作用**：采用只写入本地 Bible 草稿，可一次撤销；失败只影响它自己，不进主链。

**E5 设置 · 模型与人格。** macOS 为左侧 168px 分类（模型 / 人格 / 写作 / 外观）+ 右侧表单；iOS 为分组列表。全局设置包含供应商、五项任务的模型与参数，以及五个全局人格；**整理记忆与找方向的深度思考固定不可用**（显示「不可用」而非可点开关）。书设定另有五个「本书人格」入口，默认跟随全局，首次进入自定义只建立本地草稿，保存后才覆盖；恢复跟随全局必须确认。程序协议、模型 Profile、绑定和参数始终是全局只读边界。这是唯一允许出现 Agent 分工的界面。

**E6 导出。** macOS 为顶部下拉 sheet（520px），iOS 为底部弹层。范围（已接受的 12 章 / 全部 14 章 / 本章）+ 格式（纯文本 / Markdown）+「每章一个文件」+ 分开的「附世界观」「附人物设定」开关。只读取已保存版本，当前编辑器里未保存的本地修改不纳入；记忆导出保持独立。

### F · 人物 · 起步 · 深色（5 帧）

**F1 人物。** macOS 三栏中插入 236px 名单栏（姓名 + 「N 章有归档记录」，无记录者灰显「还没有归档记录」），右侧为编辑区：作者可编辑的姓名、身份、人物设定在上，只读的有效归档在虚线下；失效 revision 只能作为明确标注的只读预览，不能混入当前人物状态。底部动作条只有「删除」（`#A6392B` 描边）。iOS 为独立列表页 + 详情页。

**F2 新增人物。** 姓名 / 身份 / 性格三字段，其余留待后续补。macOS 模态 480px，iOS 底部弹层。

**F3 首次启动。** 居中「从第一本开始」+ 新建一本（主）/ 导入正文；下方独立一条「还没有可用的模型 → 去设置」。模型未配置**不阻塞**新建。

**F4 空书 · 第一章。** 章节轨只有 1 章，人物计数为灰色 0；意图栏三块均为空态，世界观一栏显示「还没有写 · 去写」。

**F5 深色模式。** 结构完全一致，仅换色板（见下）。正文对比度按纸 `#14120F` / 墨 `#E8E2D6`；赭石提亮为 `#C89552`，通过色提亮为 `#7FA487`；斜纹在深色下为 `repeating-linear-gradient(45deg,#211E19 0 6px,#191612 6px 12px)`。

## Interactions & Behavior

### 状态的固定位置（作者只需学一次）

| 语义 | 位置 |
| --- | --- |
| 有任务在进行 | 任务带（正文上沿） |
| 正文安不安全 | 任务带右侧那句话 |
| 检查结论 | 意图栏「证据」档 |
| 归档结果 | 意图栏底部 / 第三档 |
| 失效 | 原地转灰或打斜纹，不消失 |
| 全书记忆健康 | 章节轨的状态点与斜纹底 |

### 主动作的状态机（底部动作条 / iOS 动作坞中央）

```
空章  → 生成这一章
生成中 → 取消生成
生成完成且检查通过 → 接受这一章
正文已改且有旧结论 → 重新复查
检查通过或无结论 → 接受这一章
已接受 → 开始下一章（重开为次级动作）
```

同一时刻只有一个主按钮。危险动作（重开、未通过仍接受、删除人物）走确认层，且确认文案必须列出**具体后果**，不使用「不可撤销」这类抽象警告。

未通过仍接受时的确认文案范式：「这一章会被记为完成，检查发现的 1 处越界不会再提醒你。」

### 动效（只解释状态变化与空间关系）

| 动效 | 时长 / 曲线 | 用途 |
| --- | --- | --- |
| 任务带压下 / 收回 | 180ms ease-out | 任务开始与结束 |
| 正文淡入替换 | 约 300ms | 通过门禁后正文原子提升 |
| 呼吸（`opacity .32 → .95`） | 2.6s ease-in-out 循环 | 后台有任务在动 |
| 光标闪烁 | 1.1s ease-in-out 循环 | 编辑焦点 |
| 下游染斜纹 | 400ms，自上而下逐节点 | 重开导致下游失效 |
| 弹层升起 | 260ms ease-out | sheet / 模态 |

`prefers-reduced-motion` 下全部关闭：斜纹与颜色本身已承载全部状态语义，不依赖动画传达信息。

### 键盘（macOS，iOS 外接键盘同套）

`⌘↩` 生成 · `⌘R` 复查 · `⌘⇧A` 接受 · `⌘\` 收起/展开意图栏 · `⌘N` 新建一本。

### 响应式

- macOS：窗口变窄时意图栏先变浮层，章节轨最后收成 44px 图标条；正文版心固定 600px，不随窗口拉伸。
- iOS：正文字号跟随 Dynamic Type；软键盘弹出时任务带上浮固定在键盘上沿，动作坞让位。

### 后端相关行为（来自能力合同，实现时注意）

- 无推送，任务状态靠轮询；轮询本身、`phase`/`job_id`/`attempt`/`revision`/`schema`、模型名、失败候选稿一律不呈现给作者。
- 无服务端自动保存：本地未保存草稿与一次撤销由客户端负责（正文元信息里的「未保存」提示即来自此）。
- 「最近创作位置」由客户端记录（后端只有 `last_opened_at`）。
- 章节列表直接返回归档健康摘要；书籍读取返回等待中与需处理计数。失效 revision 的预览只供展示，不能进入写作记忆或人物投影。
- 无搜索与分页、无灵感历史；Persona 为「全局默认 + 单书覆盖」，模型与参数仍全局唯一。
- 回到应用时先与后端对账：只有任务输入仍有效且服务端已原子提升的正文才能替换本地干净基线；若本地已有更新修改，客户端保留本地编辑并把服务端旧结果视为失效，绝不构造一个可采用的候选稿。

## State Management

每章需要的状态：

- `chapterStatus`: `empty | drafting | generating | draftReady | dirty | checked | accepted | reopened | failed`
- `bodyText` + `bodyDirty`（本地未保存标记）+ 一次撤销栈
- `intent`（Bible 文本）、`allowedCharacters[]`
- `checkedDraftSnapshot`（本机、版本化、每章最近一份有实际 verdict 的检查快照；只供失效说明，永不授权接受）
- `checkResult`: `{ verdict: passed | suspect | violation | unavailable, issues[], appliesToVisibleDraft: bool }`——正文、Bible、世界观或人物约束变化后，旧结果不能再显示为当前结论；只有本机存在真实正文基线时才标注句子差异
- `usedMemories[]`（本次写作实际用到的历史，含来源章节）
- `archiveStatus`: `stale | pending | extracting | complete | partial | failed`（与 `chapterStatus` 完全解耦）
- `taskBanner`: `{ kind, text, actions[] }`（由上述状态派生，不单独持久化）

全书级：`chapters[]`（列表项直接含归档健康摘要）、`characters[]`（设定层与归档层分开存储，归档层只读）、`worldSetting`（单一长文本）、`bookPersonas[]`（五个角色的继承来源与有效人格）、`staleFromChapter`（重开导致的下游失效起点）。

### 字体

### 排版原则（实现时的硬约束）

1. **不写解释性文案。** 不解释功能怎么用、不安抚、不重复界面已经表达的东西。文案只承担三件事：这是什么、发生了什么、下一步能做什么。
2. 层级靠三档纸的明度差与字号阶梯（16.5 / 12.5 / 11.5）表达，不靠颜色。
3. 状态色只用于小圆点与卡片边框，**绝不铺满背景**（任务带是唯一例外，且为极浅色）。
4. 图标总数控制在 6 个以内，其余一律用中文标签；`✦` 是找方向的唯一符号。
5. 空态给可行动入口，不给「暂无内容」。

## 需要产品决策的遗留问题
